# 星夜突圍 v1.2｜Blue World 整合版程式導覽

程式保持可直接開啟的 HTML＋JavaScript＋Canvas，沒有打包器或外部套件依賴。所有原始碼都已換行、縮排，主要流程有中文註解。離線包的檔案和線上遊戲使用相同邏輯。

## 從哪個檔案開始讀

| 檔案                       | 用途                                         |
| -------------------------- | -------------------------------------------- |
| `index.html`               | 網頁入口、上方選單、對話框與樣式載入         |
| `game.js`                  | 遊戲資料、平衡公式、引擎、介面、Canvas、控制 |
| `style.css`                | 基礎畫面與原始遊戲樣式                       |
| `ui-v12.css`～`ui-v15.css` | 出航選單、手冊、護盾與效果設定的補充樣式     |
| `ui-blueworld.css`         | r11 精簡 Boss 列、展開提示與手機橫向導覽     |
| `../../shared/portal.js`   | 遊戲館的休息訊息及獨立開啟時的返回連結       |
| `../../shared/fonts.css`   | 已封裝的中文字型，不依賴外站載入             |
| `assets/`                  | 背景與四種原創 Boss 圖片                     |
| `tests/`                   | 引擎檢查、介面事件模擬、自動走位壓力測試     |
| `操作說明.md`              | 玩家操作與目前的戰鬥規則                     |
| `測試紀錄.md`              | 已執行檢查、模擬條件與驗證限制               |

本整合版位於 `games/starbreak/`；遊戲內 `index.html` 使用 `../../shared/` 共用返回及字型。整個網站根目錄的 `index.html` 是遊戲館入口，發布時請保持兩層路徑，不要把遊戲檔案散放在根目錄。

公開版本改顯示 1.2，但來源 v1.5 玩法保留。`VERSION = 1` 代表存檔格式；`KEY`、`RUNKEY` 保留原值，不跟著畫面改版，以維持舊備份相容。

`showGame()` 建立 `boss-hud` 與 `battle-field` 兩個相鄰區塊；`ResizeObserver` 觀察戰場尺寸。`showBossStatus()` 用原本的對話框顯示完整資訊並暫停。`akane-portal-pause` 事件會清除輸入、暫停並保存；`frame()` 在遊戲館休息／背景分頁時不繪製或推進戰鬥。

## `game.js` 的六個區塊

1. **遊戲資料**：`WEAPONS`、`SHIPS`、`DIFFICULTIES`、`BOSS_PROFILES`、`DEFAULT_CONFIG`。名稱、武器特性、難度與設定上限放在這裡。
2. **存檔驗證**：`validateRun()` 檢查資料，再交由 `migrateRun()` 轉換缺少欄位的舊版本。
3. **戰鬥引擎**：`Engine` 管理移動、生成、攻擊、命中、升級、商城與結算。它不依賴 DOM，可以在 Node 執行。
4. **介面**：`showHome()`、`syncPlan()`、`showGame()`、`updateHUD()` 和說明／設定畫面。
5. **Canvas**：`draw()` 與各種繪圖函式。它讀取引擎狀態，畫面選項不參與戰鬥判定。
6. **輸入**：鍵盤事件、`pointerDown()`／`pointerMove()`／`pointerUp()` 和動畫更新 `frame()`。

## 先理解這些名稱

- `profile`：永久進度，包含研究、晶礦、成就與效果偏好。
- `engine.r`，經常縮寫為 `r`：本次遠征的完整狀態。
- `r.p`，縮寫為 `p`：玩家位置、生命、等級與技能冷卻。
- `e`：單一敵人；`e.type === "boss"` 時還有護盾、階段與連發隊列。
- `e.adaptive`：Boss 出場時固定的接戰配置，包含生命、護盾、火力指標及攻擊倍率。
- `dt`：本次更新經過幾秒。暫停、商城及升級畫面不累計戰鬥時間。
- `rng`：有種子的戰鬥亂數。效果不得消耗它，否則關光效也會改變敵潮。

## Boss 平衡怎麼計算

入口是 `createBossEncounter(r)`，由 `spawnEnemy("boss")` 呼叫。分四步：

1. `estimatePlayerPower(r)` 估算武器單體火力、射速、進化、暴擊、研究和遺物；範圍／近身武器有覆蓋率折算。防禦指標另算，玩家當前殘血不參與。
2. 用線性的等級項和較緩的火力項混合，得到總耐久預算。
3. 將預算分配給本體、裝甲、初始護盾及預計恢復的護盾。
4. 以有上限的成長倍率調整出招、彈量、彈速、預警、傷害和護衛壓力。

主要參數集中在 `BOSS_BALANCE`：

```js
const BOSS_BALANCE = {
  referenceDps: 22,
  referenceSeconds: 22,
  levelGain: 0.5,
  levelWeight: 0.35,
  powerWeight: 0.65,
  powerExponent: 0.8,
};
```

其中 22 是校準參考值，**不是保證每場只打 22 秒**。火力指標是估算，不是實際傷害計。

計算關係可以寫成：

```text
等級項 = 1 + (玩家等級 − 1) × 0.5
火力項 = (估算火力 / 22) ^ 0.8
參考火力 = 22 × (等級項 × 0.35 + 火力項 × 0.65)
總預算 = 22 × 參考火力 × 難度預算倍率 × 耐久選項 × 模式倍率 × 護盾修正
本體 = 總預算 / (裝甲折算 + 護盾比例 × 所有預計護盾份數)
```

本體最低 70 生命，並四捨五入。護盾修正是緩和的 0.22 次方，讓重盾有差異但不再直接疊成數倍血量。限次充能預算採每個階段最多兩次恢復計算，實際快速破關時可能不會全部發生。

想稍微降低所有 Boss 耐久，可調小 `referenceSeconds`；想只改災厄，調整 `BOSS_PROFILES` 最後一列的 `bossHp`。這個名稱沿用舊版，但現在代表**總耐久預算倍率**。

想讓高等級成長更快，調 `levelGain`；想讓裝備成長較緩，調 `powerExponent`。`levelWeight` 和 `powerWeight` 應合計 1。建議一次改一個參數，再比較低等級、完整構築與六檔難度。

## 攻擊、護盾與階段

- `bossAttack()`：每隻 Boss 五種主招式，`attackCycle % 5` 輪替。
- `bossLayers()`：決定主招之外疊幾個獨立通道；低等級弱火力減少一重。
- `bossCooldown()`：決定下一次施招間隔，獨立於彈幕密度。
- `queueBarrage()`／`updateBarrages()`：連發隊列讓前一招尚未結束時，下一招可以接上。
- `enemyShot()`：建立敵彈，使用 `ownerId` 尋找該 Boss 的固定配置。
- `addHazard()`：建立先預警、後傷害的圈或光束。
- `hitEnemy()`：武器增幅、暴擊與控制 → 防護罩阻擋 → 裝甲減傷 → 本體。
- `restoreBossShield()`：階段或限次恢復；不是每幀補滿。
- `updateEnemy()`：移動、冷卻、階段轉換與護衛生成。

Boss 生成後，`maxHp`、`maxShield` 和 `adaptive` 不再追著玩家的最新等級重算。因此中途升級會有實際優勢。舊存檔轉換只做一次，按各自的剩餘百分比調整兩條血量；再次讀檔維持相同配置。

## 模式與效果修改位置

模式使用 `modeRule(r)`，返回 `campaign`、`endless` 或每日三種主題。實際規則分布在 `prepareWave()`、`enemyPool()`、`bossSummon()`、`bossAttack()` 和 `enemyShot()`；不能只改名稱就說玩法不同。

`combatImpact()` 只加入短命效果與有上限的鏡頭脈衝，不修改敵人／玩家位置或時間。`presentationSettings()` 決定效果品質，`drawImpact()`、`drawCharge()`、`drawModeAccent()` 和 `drawBeam()` 負責呈現。Canvas 最後重畫預警外框，避免法陣遮住危險區。

敵彈 480、危險區 60、每隻 Boss 連發隊列 8、特效 220 的上限要維持；降低演出只應改繪圖，不應少生成敵彈。若改攻擊形狀，繪圖與 `step()` 中的碰撞條件要一起檢查。

## 執行檢查

已安裝 Node 的話，在離線包根目錄執行：

```bash
node --test tests/*.test.cjs
node tests/ui-smoke.cjs
node tests/balance.cjs difficulties
node tests/balance.cjs boss-trial
node tests/balance.cjs boss-endgame
```

Site 專案內也用相同指令。`boss-endgame` 是直接給 Lv.25、六把進化武器與能力滿級的壓力測試；`STARBREAK_RESEARCH=max` 可加滿永久研究。`STARBREAK_MODE=daily` 或 `endless` 切換模式，`STARBREAK_SEED=52139` 切換種子。

引擎檢查涵蓋倒數、進化、商城、護盾、配置固定與舊存檔轉換。介面檢查使用模擬 DOM／Canvas，不驗證真實 CSS 排版、手機效能或音效聽感。平衡模擬保留真實傷害與碰撞，但自動走位策略不能代表所有人的操作。
